# 出口储胶槽回填修复

当前结果为 `BOUNDED_OUTLET_GROOVE_REPAIR_PASS`：负半恢复了原定 Z45～68 mm、Y=±26.75 mm、名义宽 0.8 mm、深 0.2 mm 的两条浅储胶槽。这里只关闭联合法兰回填槽的几何缺陷；密封材料、施胶/固化、实物气密及承力验收没有因此完成。

## 改动及来源

只在 `cad/feeder-integrated-candidate.scad` 的 `ic_host_half` 中，将 `seam_reservoir_cuts()` 作为负半条件差集放在原壳、背梁耳和出口法兰全部 union 之后。X=0 合壳硬止面、42.5 mm 球道及管口尺寸不变。没有夹入平垫，也没有修改原槽的尺寸契约。

冻结时整文件 SHA256 为 `0cf66a4354edf71dc75160810e8dbc9c2119346896d9b305a491a6850d7818c3`；单独 `ic_host_half` 模块 SHA256 为 `4698e67adc54b4834cb45256c707d32ddf91f189c7f5438860517d0b5e4c7876`。根任务可以继续整合此文件其他模块；后续整文件身份应以新的整合报告为准。

原源、正负半 STL、整合报告和原路径检查报告保存在 `output/outlet-groove-fix/before/`，身份见 `manifest.json`。原负半 SHA256 为 `f8a2aba50cdbd5ce71a9f51bc75b81e8ed0895dfb6150cc6a189ca2ce4bf66c4`。其实际槽底在 Z45～48 mm 的面积为零；旧挤出路径的 24 个探区也被模型路径占满，这个反例没有被覆盖或删除。

## 数值检查边界和保留的失败记录

脚本先复制完整递归依赖快照再导出，防止其他整合工作在运行中混入。最终报告记录的依赖在本次运行结束时与工作区一致。实际 STL 剖面、完整平面工作面及整件数值布尔相互核对；剖面采样本身不被宣称为所有截面的证明。

第一次导出包装器遗漏了原顶层的 `$fn=72`，导致不同细分几何，已判无效并保存到 `rejected-missing-resolution/`。修正包装器显式引入原参数后，正半与旧件字节相同。

CGAL 对旧、新已导出 STL 做精确差集时产生非流形结果警告；该项没有算通过，原输出在 `rejected-exact-import-difference/`。后续报告的整体布尔检查明确使用 Manifold 数值后端，不称精确集合证明。

数值布尔的“新增材料”和“新件与 cutter 相交”输出分别带有 8 和 2,048 个边界三角面。没有仅凭接近零的体积将其忽略：逐个完整三角形确认位于原 cutter 的既有平面多边形内，并比较同一平面正反向面片覆盖。两者都没有未匹配面，正反面差面积均为零，最大平面偏离约 1.42×10⁻¹⁴ mm。比较用 10⁻⁷ mm 坐标容差，仅为数字几何容差。原回填件作为阳性对照，产生 0.932244116 mm³ 实体且该边界分类明确拒绝它。移除原 cutter 之外的材料检查为空。

## 复跑与后续

在项目根目录运行：

```sh
/Applications/FreeCAD.app/Contents/Resources/bin/python -B analysis/outlet_groove_fix.py --export
```

去掉 `--export` 只复核现有快照和输出。完整结果为 `output/outlet-groove-fix/report.json`。原料面片和警告输出保留用于复查；本脚本没有更改切片设置、重切或发打印任务。

原负半 G-code 对应修复前网格，不能作为新负半制造产物使用。待根任务完成统一整合后重新切片和核对新槽的挤出空域；本次不提前宣称 0.4 mm 喷嘴已经保留了新恢复段，也不重复制作无关试片。
