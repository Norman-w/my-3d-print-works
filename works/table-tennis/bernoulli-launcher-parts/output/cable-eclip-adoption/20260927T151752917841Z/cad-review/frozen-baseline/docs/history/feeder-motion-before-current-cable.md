# 总 3D 场景

局域网入口：`http://192.168.7.187:8877/feeder-motion.html`。

## 场景约定

一个持久的 Three.js 场景保留全部已有装配。六个观察位置只改变相机，不替换模型、不重置装配变换、不改变显隐，也不归零当前动作。显隐通过右侧图层和完整模型目录独立控制；外壳可选实体、透明或剖开。

默认加载送料 36 项与旋转头工作档 11 项，共 47 项。退出保持叉为第 48 项，勾选后按需加载，旁置展示以区别于工作档。每个资源只建立一次场景节点；取消勾选只隐藏，重新显示复用原节点。"加载并显示全部模型"将 48 项全部加载并展示。

场景还保留原球仓、球、钢丝软管、风机、斜三通及出球管参考外形。这些外部外形和管长没有实测，不能用作裁管或装配避让尺寸。

## 模型来源与运动

送料使用 `output/launcher-final-history/before-frame-y-guide` 的33个已导出打印件，以及原五金、PC参考、弹簧参考。共36资源；不把后续未通过制作验证的修订替换进本次展示。旋转头使用既有 `output/revision-review/models/spin/` 资源。发布器核对全部哈希，并在 `motion-manifest.json` 的 `assembly_catalog` 列出48项。

所有原STL顶点均保留原装配坐标，没有逐件居中。送料仅整组变换到原斜支路：`world=[-155+(z-x)/sqrt(2), -155+(z+x)/sqrt(2), y]`；旋转头为 `world=[380+z,x,y]`，其承插止口与原出球PC管端面x380对齐。

原合并五金包含74个连通体、52720个三角面。`scripts/build_motion_hardware.py`仅按已有运动分成固定、四组挡指、运动弹簧端共6组，逐面保留原法线、顶点和绕序。完整原资源仍在目录中，以6个子网格渲染，取消此前重复的程序肩销和弹簧销。分组证明在 `motion-hardware/hardware-manifest.json`，不是制造或碰撞验证。

原弹簧STL的固定端环不动、运动端环平移，中间包络在源文件两端位置之间伸长；不使用另一套程序弹簧替代。球流转与速度仍是演示时序，中途未完全扣到放球位即松手时，球留在待发位。

## 扳机操作叠加

`web/trigger-overlay.mjs`只包含手、握把、扳机及拉索传动方案，不再绘制另一套风机、三通、送料壳和滑架。拉索末端随原凸轮架现有连接片表面参考点 CAD `[-68,24,13+u]` 移动。该点仅用于说明运动对应关系，不是已完成的安装接口。

近端扣动12mm对应原送料行程20mm，远端回位为释放。原凸轮架上的指环和背梁握把完整保留；新增手柄、支架、拉索路线、锚点、作用力和安装避让仍待机械落实。它们在界面中明确为可单独显隐的方案叠加，不宣称打印结构已改好。

## 维护与发布

同一场景支持显示导轨、挡指外滑块、肩销与槽壁三类润滑位置；球、球道、挡指接球端与摩擦垫保持干燥。润滑剂仍需厂家明确兼容PETG和PC。

```sh
python3 scripts/build_feeder_motion.py
python3 scripts/verify_launcher_lan.py
```

发布仅分组现有网格、复制前端资源并校验LAN提供的字节，不执行CAD重导出、切片或制造验收。相机/模型身份、显隐缓存、48项加载和扣动/释放在浏览器中验证。
