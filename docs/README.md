# SmartPaddle — 智能乒乓球拍分析系统

SmartPaddle 是一套端到端的**智能乒乓球拍系统**，通过在球拍结构中嵌入压电传感器阵列和惯性测量单元（IMU），实时捕捉击球位置、挥拍轨迹和姿态数据，为乒乓球运动员、教练及球拍制造商提供精确的运动分析能力。

---

## 核心功能

### 精准击球定位
- 球拍四角各布一枚压电陶瓷传感器；当前 C5 沿用 MCP4728 四路门槛与 TLV9034 数字边沿，再以 GPIO ISR + CPU cycle 锁存振动波到达时间差
- 通过多项式回归模型将 TDOA 转换为拍面毫米级 XY 坐标
- 支持 **每副球拍独立标定**，消除个体制造偏差，标定 RMSE < 3mm

### 挥拍姿态追踪
- 内置 IM948 十轴 IMU（陀螺仪+加速度计+磁力计+气压计）；当前固件 100 Hz 输出，250 Hz 为精简订阅后的待实测目标
- 服务端运行 **Madgwick AHRS 姿态滤波器** + 零速更新（ZUPT）轨迹重建
- 实时输出球拍三维方向、挥拍速度与空间轨迹

### 3D 实时可视化
- Web 端基于 Three.js 的球拍三维模型，IMU 数据实时驱动旋转
- 击球点在拍面上以彩色标记显示，随手感反馈
- 支持数据回放与历史会话浏览

### 球拍 CAD 参数化建模
- 四视图贝塞尔曲线编辑器（拍面正视图、手柄正视图、柄侧视图、柄底截面）
- 官图叠加描摹 + mm 参考网格校准，精确复刻任意品牌拍型
- 生成的曲线直接驱动 3D 放样模型，所见即所得

### 完整的标定工作流
- 标准网格纸打印 → 逐点敲击采集 → 自动拟合多项式模型
- 标定结果持久化存储，多副球拍可切换

## 系统架构

```
球拍硬件（C5 ESP32-S3）      云端 / 本地服务器（Go）          Web 前端（React + Three.js）
┌─────────────────┐       ┌────────────────────┐       ┌─────────────────────────┐
│ 4× Piezo 传感器  │       │                    │       │                         │
│ IM948 十轴 IMU   │──WiFi/WebSocket──▶│  SQLite (WAL)       │──REST API／WebSocket──▶│  Live · Shape · Sessions │
│ WS2812 LED      │       │  TDOA 定位引擎     │       │  Calibrate 四大模块     │
│ 3D 打印外壳      │       │  IMU 姿态／轨迹    │       │                         │
└─────────────────┘       └────────────────────┘       └─────────────────────────┘
```

| 层级 | 技术栈 | 说明 |
|------|--------|------|
| **传感器/固件** | C3: ESP32-C6；C4/C5: ESP32-S3-WROOM-1-N16R8 | MCP4728 + TLV9034 四路边沿 TDOA + 十轴 IMU |
| **外壳（模型）** | OpenSCAD（`enclosure/`） | 四零件分体壳；版本见下方「模型」线 |
| **电路板** | 飞线 → FPC → 刚性骨架 PCB | 版本见下方「电路」线；与模型线独立编号 |
| **后端** | Go, SQLite, WebSocket | REST API / 实时数据管道 / 定位算法 / 标定管理 |
| **前端** | React, TypeScript, Three.js | 3D 可视化 / 贝塞尔 CAD / 标定向导 / 遥测仪表 |

## 版本命名（多段）

整机标识采用 **三段命名**：`模型.电路.软件`，另有独立的**主线**（产品能力代际）。

**格式示例：** `M7.C5.0.1.0` = 模型 M7 · 电路 C5 · 软件 `0.1.0`

| 段 | 含义 | 编号方式 |
|----|------|----------|
| **主线** | 产品能力代际（IMU 架构等） | `主线 Vn`，与三段并列，不塞进中间位 |
| **模型** | OpenSCAD / 外壳结构 | `M` + 整数（`paddle_shell.scad` 等） |
| **电路** | PCB / 飞线 / FPC 方案 | `C` + 整数（Gerber / `pcb/`） |
| **软件** | 固件 + 服务端 + 前端发布物 | 语义化 `MAJOR.MINOR.PATCH`（计划自动发版） |

## 当前状态

**当前组合：** 主线 **V1** · 模型 **M7** · 电路 **C5** · 软件仍早期，整机硬件标识为 **M7.C5**。M7 的事实依据是现行外壳已相对 M6 增加受保护 14500 局部适配、两束实购 MX1.25 线的独立通道、8 个实际 PZT 焊盘中心让位，以及与主板 B3U/ESP32 天线边界联动的机械门禁；电路拓扑没有因此再变，仍为 C5。外壳打印件与预览清单使用当前模型号 `paddle_m7_*`；PCB、同步脚本和交接文件保持跨版本通用名。OpenSCAD 连续承力生成链内部仍保留 `m6_*` 模块/参数名，不代表当前整机版本。

**硬件（当前）：** **C5** = 单 IM948 + ESP32-S3-WROOM-1-N16R8 + MCP4728/TLV9034 PZT 前端 + TPS62162 主电源 + 独立尾板 IP5305T/限流/USB/按键/灯；当前两板已同步但尚未布线。资料：[当前布线交接](../pcb/ROUTING_HANDOFF.md) · [电源架构重整](power-architecture-rework/README.md) · [外壳](../enclosure/README.md) · [PZT 前端](PZT/comparator-frontend.md) · [IM948](IM948/README.md) · [主尾板线束](../pcb-tail/ADAPTER_HARNESS.md) · [尾板 Type-C](usb-c-vertical-16p-short/README.md) · [尾板/拍柄 3D 干涉](tail-handle-interference/README.md)。C4 计划、制造审计与 C5 早期单 8P 计划继续保留为历史资料，不再定义当前板。待办见 [`TODOS.md`](../TODOS.md)。

## 商业应用场景

### B2C — 运动员 / 教练
- **击球点热力图**：发现甜区和击球习惯偏差
- **挥拍一致性量化**：对比训练与比赛的轨迹差异
- **远程教学**：教练通过 Web 端实时查看学员数据

### B2B — 球拍制造商
- **品控检测**：标定每副球拍的定位精度，量化出厂一致性
- **R&D 迭代**：快速贝塞尔建模 → 3D 预览 → 放样输出，加速新型号开发
- **品牌定制**：为品牌方提供带 Logo 的联名分析平台

### B2B — 体育科技
- **赛事数据采集**：多球拍同时接入，生成比赛击球分布统计
- **数据 API 开放**：REST / WebSocket 接口供第三方系统集成

## 技术指标

| 指标 | 数值 |
|------|------|
| TDOA 时间分辨率 | CPU cycle 锁存（非 12.5 ns RMT） |
| 定位 RMSE（标定后）| < 3 mm |
| IMU 上报率 | 当前固件 100 Hz @115200；250 Hz 为精简订阅后的待实测目标 |
| PZT 时间源 | C5 使用 TLV9034 推挽边沿 + CPU cycle；ADC 仅 DNP 调试窥探 |
| WebSocket 延迟 | < 10 ms (本地) |
| 数据库 | SQLite WAL，支持 10万+ 击球记录 |

### C3 / C4-C5 算力差异

C3 的 ESP32-C6 无硬件 FPU，板端融合需控制浮点开销；C4 升级到带硬件浮点的 ESP32-S3-N16R8，C5 继续沿用。主线仍是单 IMU V1，升级 MCU 不等同于切换到双 IMU V2。
