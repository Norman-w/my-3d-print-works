## 短路机理与根因

修复前，线缆插头会把同功能的 VBUS 触点并到同一导体：正确接 `vbus` 的 A4 因而与错误接 `GND` 的 A9/B4 相连；同理，正确接 `GND` 的 A1/A12 会与错误接 `vbus` 的 B12 相连。即使线缆另一端悬空，也会在本板上形成 VBUS–GND 硬短。这与 C4 从约 4.1 kΩ 降为近 0 Ω、Hub 进入保护的现象完全一致。

`pcb-tail/main.ato` 的 A/B 面 VBUS、GND、CC、D± 逻辑连接一直正确。历史变更 `d9456dd` 在换入自定义 footprint 时，没有按该具体连接器的实际几何逐触点重建已实例化 J1 的 pad-net 关联；例如 A9 被置为 GND、B12 被置为 VBUS、A8 被置为 VBUS。常规 KiCad DRC 只检查“板文件声明的网络”，不知道供应商触点语义，所以错误旧板仍可报告 0 违规、0 未连接。

## 封装语义修复阶段的变更与验证

- 封装、Atopile 元件定义和当前 PCB J1 均改为直接使用数据表触点名，避免数字转译；A8/B8 明确 NC。
- 生成器改用短脚数据表尺寸，并生成数据表对照预览。连续运行两次所得 footprint 哈希一致，生成可重复。
- `python3 pcb-tail/scripts/audit_usb_16p_j1.py` 对主 PDF 哈希、17 个逻辑 pin、16 个物理触点、两个 S1 槽、局部坐标、尺寸及 PCB 网络逐项检查：**PASS**。
- Atopile 0.12.5 隔离构建验证了 17 个按名称绑定的逻辑 pin；不能使用同名 `signal A1` + `pin "A1"`，因为该写法会产生空 pinmap。
- 与修复前 PCB 比较：379 段走线、64 个过孔、4 个铜区逐字节不变；24 个 footprint 中只有 J1 变化，J1 原点/角度不变。**该初始修复阶段没有布线，也没有移动 USB-C 之外的电路。**
- 修复前板及对应旧 footprint 的 KiCad CLI DRC：0 违规、0 未连接。修正 J1 语义而保留旧铜线后：46 项违规（45 error、1 warning）和 8 项未连接，其中包含 13 项不同网络短接。结果证明旧铜线与正确触点不兼容。
- `check_connected.py --component J1 --verbose` 另行确认 `usb_dn_conn`、`usb_dp_conn`、`cc2`、`vbus` 在正确 J1 触点处与旧走线断开；这与 KiCad 的 8 个未连接结果一致。该工具同时把无网络机械/NC pad 归入 `net 0`，因此制造判定仍以逐触点门禁和 KiCad DRC 为准。
- 尾板制造导出现在先运行逐触点门禁，再运行 DRC。初始修复阶段的试跑在 DRC 处按预期中止，未产生 Gerber、钻孔或 ZIP。
