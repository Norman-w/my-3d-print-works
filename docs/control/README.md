# ESP32 控制层边界

## 当前状态

当前工程已经有网页控制逻辑示意和电气时序仿真，但还没有真实的 ESP32 固件、GPIO 绑定、编码器读取、驱动器接线或安全回路。网页里的动画不能被当成控制器已经可用。

本目录的 [esp32-control-contract.json](./esp32-control-contract.json) 只冻结不会轻易漂移的控制拓扑：

- 当前机械站位是 5 列 × 3 层，共 15 个抽屉；底部保留 1 层服务空间；
- 选站轴和抽屉动力轴是两个独立闭环轴；
- 永磁离合是机械动作，ESP32 负责选站、停轴、确认和互锁；
- 电机型号、驱动器型号、电机电压和屏幕型号仍然是待冻结项；
- 急停、硬件驱动禁止、HOME、开闭限位和离合反馈不能被软件超时替代。

## 真值层级

1. `cad/openscad/enclosure/cabinet_params.scad`：箱体、层距、服务区和机械坐标真值。
2. OpenSCAD 导出契约：站位、运动轴、几何包络和装配实例真值；蛇链求解器必须直接读取这些参数，不能再维护一套 250/44/5×3 的 Python 副本。
3. `docs/control/esp32-control-contract.json`：控制状态、反馈名称、安全互锁和前面板接口真值。
4. `index.html`：解释和仿真页面，不得重新发明电机型号、站位数量或行程。
5. 未来的 ESP32 固件：实时动作真值；网页只能通过高层命令和状态事件与它通信。

## 运行闭环

```text
BOOT → SELF_TEST → HOME_SELECTOR → IDLE
  → SELECT_STATION → VERIFY_CLUTCH
  → OPEN_DRAWER / CLOSE_DRAWER
  → RELEASE_CLUTCH → RETURN_SAFE
```

任一编码器、限位、离合或驱动故障未确认，都进入 `FAULT`，硬件禁止电机输出。返回选站轴之前必须释放离合；到位后由机械止挡或锁块承载，不能让电机持续顶住。

## 前面板接口边界

当前箱体的 X− 侧服务区为 44 mm，底部有 1 层服务空间。推荐把屏幕和指示灯放在前方的控制侧表面，把 ESP32、驱动器、降压、电源端子和保险丝放在可拆的底部电子安装板；下方横条优先放急停、复位和电源入口。若选择的屏幕超过 44 mm 控制区的可用宽度，必须调整面板包络并重新做抽屉/链条干涉检查，不能把屏幕强行塞进抽屉格或蛇形链回程区。

屏幕安装件必须由实际模块外包络参数生成，包含可拆面框、Boss/螺丝孔、排线弯曲空间和应变释放；LED 只做状态显示，不承担安全判断。

## 禁止回流的旧假设

- 不把仓库中早期遗留的 FreeCAD/4 列/3 层实验文件当作当前 5×3 机械装配；当前工程实际只走 OpenSCAD → STL → Three.js；
- 不把旧的 12 路、NEMA17、TMC2209、TR8×4 候选当成已选硬件；
- 直流编码器电机不能接 TMC2209；TMC2209 只在最终选择步进电机时启用；
- 不用浏览器动画、定时器或电机运行时间替代编码器、限位和离合反馈；
- 不把公网网页直接暴露成电机 GPIO 控制入口。

蛇链运动 JSON 还必须携带 `cabinetGrid` 和 `pinCount`，并由同步校验器回读 OpenSCAD 参数；链节数是当前几何求解结果，不得在校验器里再写死成旧尺寸对应的常量。

下一阶段应先冻结两台闭环执行器和传感器接口，再创建 `firmware/esp32/`；固件创建前不把本文件中的 `pending-*` 字段改成假定型号。
