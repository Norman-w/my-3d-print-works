前三件各两个辅助体仍被原生 3MF 标为 `support_enforcer`，不是正常模型。六个辅助体从各自输入 3MF 到实际输出 3MF 的全体有向三角面、姿态、局部范围和角色均重新核对，不能只凭 bounding box 相同认定。主盖只有一个正常模型，无辅助体；G-code 实际支撑路径计数为 0。

## 清理路径与限制

前三件的原 V3 审查继续有效。扳机/端盖原“全部支撑必须在两窝内”检查仍为失败；后来对 3 / 7 条首层命令的独立分类证明它们是 1 / 2 个**在整件 XY 投影之外、只占床面 0…0.1 mm、与 Brim 相触的残料岛**。它们走取件后的清床路径，不走螺母孔。其余支撑在原浅窝中，可在装五金前沿反生长方向退出；该名义通路不保证同料 PETG 易脱离或工具容易抓取。不得把这几个外部岛再次误作孔内卡死，也不得删掉原严格失败记录。

现有证据仍不保证 0.2 mm 支撑间隙上的桥接无下垂，不保证支撑无残渣、不伤承面、不影响尺寸、扭矩或强度。主体横向止挡窝、M6/止挡圆孔曲顶等既有有限桥接不在此次局部肩面修正范围。报告中的残余无投影承托长度是曲线路径片段，不是相同长度的直线自由跨度。

用户已确认 PETG 和 PEI，但未指定 PETG 品牌或 PEI 纹理；当前 Generic PETG / Textured PEI 配置仍是明确的工艺假设。绑定通过只证明**当前几何可复用这一份已有数字制造证据**，不构成实物验收或自动打印许可。

## 使用与再验证

`manifest.json` 是统一清单可读取的适配项；每条包含 `instance_id`、`current_stl_sha256`、选择的切片、全部 artifact/profile hashes、姿态、支撑清理与物理限制。完整分件结果在 `parts/<零件名>/binding.json`，实际原生配置在相邻 `resolved-project-settings.json`。正式统一制造脚本本轮未修改。

只读重核命令（不会导出、切片或打印）：

```sh
/Applications/FreeCAD.app/Contents/Resources/bin/python output/current-manufacturing/input-process/bind_current_input_process.py --check
```

任何当前模型、依赖源、配置或切片散列变化都会阻止按本绑定直接复用。原绑定检查日志为 `binding-run.log`，独立只读重核日志为 `verify-run.log`。
