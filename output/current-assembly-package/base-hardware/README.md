## 来源与重现

[review.py](review.py) 人工审过实际模块调用，再由源参数展开安装位；它不是完整 OpenSCAD 解释器，也不靠网格连通块推算螺钉数量。一颗螺钉的杆与头只计一个实物，弹簧的线圈／端环也只计一个实物。

- 送料入口：[launcher-final-assembly.scad](../../../cad/launcher-final-assembly.scad) 的 `la_fixed_hardware()`、`la_moving_hardware()`，以及 `la_show()` 单独调用的 `rs_spring()`。
- 旋转头入口：[spin-complete-hardware.scad](../../../cad/spin-complete-hardware.scad) 的 `sch_hardware("all",…,held=false/true)`，另加 `sch_spring()`。不再叠加旧 `hardware_reference()`、`pull_hardware()`、`added_nuts()` 的展示副本。
- [source-modules.json](source-modules.json) 存调用相关模块正文、文件行号、参数表达式／值及源 SHA256。
- [inventory.json](inventory.json) 的每个 `instance_id` 是一个实物，含规格、数量 1、安装坐标／轴向、运动归属、模式、源模块。送料为 CAD 坐标；旋转头为安装到整机之前的旋转头局部坐标。列出的运动位置为 `t=0 / float=0 / preload=0`。

复跑：从仓库执行 `python3 output/current-assembly-package/base-hardware/review.py`。脚本先完成独立枚举，最后才读旧 JSON 比较，不用旧数量驱动新清点。此运行未执行几何导出、切片、采购或实物操作。

与 [旧送料 JSON](../../manufacturing/feeder-hardware-bom.json) 对比：22 类逐项相符，未匹配项为空。当前 `pin-D3x6` 对应旧 ID `seam-pin`，均为 2 件；初稿的 `locator-pin` 别名错误已修正，不是漏销。旧报告的 `launcher-final-assembly.scad`、`feeder-hardware-clearance.scad` 散列已变化，因此旧源身份不能直接代替本次重新清点。

## 合并拉索增量的唯一接口

`inventory.json.cable_adoption_hand_off` 给出精确 ID：

1. 从本表删去 4 个 `beam-host/*/bolt`（M4×20）和 4 个 `beam-host/*/washer`（OD9×0.8），合计 8 件，因为正式拉索系统删除整个 `sh_bolts()`。
2. 保留同四安装位的 `beam-host/*/nut`，合计 4 颗 M4 螺母，不重复购买／计件。
3. 输入端新 M4×60 与新头侧垫片仅从拉索增量表加入一次。其它拉索、调节器、桥架、端盖及路线保持件由增量表负责。

因此最终套件的算式起点是 **228−8＝220 件＋拉索增量**；工作档在同一并集里隐藏保持叉的螺钉和垫片，不能另加一套 31 件旋转头。这个 220 不是最终总数。

## 规格与验收限制

- 尺寸和候选型号来自当前 CAD 与既有 [送料规格说明](../../../docs/final-feeder-hardware.md)，未新查库存或下单。JSON 不把候选登记为已购、已完成实配或制造放行。
- 入口 M2.5 螺钉候选头部最大 Ø4.5×2.5，而 CAD 仍保留较大的 Ø5×3 参考包络和旧“SKU 未锁”注释；两者已分别记载，不能称逐实体相同。两片 0.5 mm 垫片为名义厚度，完整厚度公差仍未知。
- 某些早期 M3 垫片在展示 CAD 中是与螺杆重叠的实心薄圆盘，ID3.2 取自既有尺寸选择；本次没有伪称其显示网格已有真实内孔。螺纹均为名义包络，不据此推导预紧力。
- OD12×0.8、OD9×0.8、OD8×0.5 三种 M4 垫片不混用；尤其回位弹簧两端仅计小 OD8 的四片。肩销公差、弹簧真实力、打印承面强度与工具实物都未因数量对齐而自动通过。
- 两片入口柔衬、20 mm 宽卸载织带、SCS2700 LM／Scotch70 密封材料在 JSON 单列，材质／长度／用量未知，未伪造成固定采购数量。打印件、现有风机、PC 管、软管、三通、备件与包装倍数均不进入上述金属／弹簧件数。
